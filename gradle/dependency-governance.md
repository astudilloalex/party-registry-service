# T005 dependency governance

The build retains Java 25, Gradle Kotlin DSL, Gradle Wrapper 9.3.1, and the
pinned Quarkus 3.33.3 enforced platform. Maven Central and the Gradle Plugin
Portal are the only configured repositories; local Maven resolution is
intentionally excluded so workstation-local artifacts cannot change a build.

## Production capabilities

All `io.quarkus` declarations below are versionless and therefore resolved by
the enforced Quarkus BOM.

| Capability | Declaration | Reason |
|---|---|---|
| CDI/bootstrap | `quarkus-arc` | Existing Quarkus composition baseline. |
| Reactive REST/JSON | `quarkus-rest-jackson` | Reactive `/api/v1` inbound adapter and explicit transport JSON mapping. |
| OpenAPI | `quarkus-smallrye-openapi` | Runtime publication of the approved OpenAPI contract. |
| Validation | `quarkus-hibernate-validator` | Jakarta transport-boundary validation without moving rules into the domain. |
| Reactive PostgreSQL | `quarkus-reactive-pg-client` | Non-blocking, parameterized PostgreSQL adapter; no ORM is added. |
| RabbitMQ | `quarkus-messaging-rabbitmq` | Reactive RabbitMQ publication and publisher-confirm integration. |
| Health | `quarkus-smallrye-health` | Separate liveness/readiness signals. |
| Metrics | `quarkus-micrometer-registry-prometheus` | Low-cardinality operational metrics and Prometheus exposition. |
| SBOM | `quarkus-cyclonedx` | Build-time CycloneDX metadata for the independently reviewed application dependency graph; it adds no business runtime capability. |

No Redis, ORM, production PostgreSQL JDBC driver, authentication provider,
remote logging/KMS client, resilience convenience library, cache library,
module split, or speculative service client is introduced.

## Verification capabilities

`quarkus-junit` supplies the Quarkus/JUnit integration already present.
Testcontainers 2 JUnit, PostgreSQL, and RabbitMQ modules (using their
`testcontainers-*` artifact names) are pinned consistently to the Quarkus
BOM-aligned version `2.0.4` and
support only integration tests. ArchUnit `1.5.0` is pinned because it is
outside the Quarkus platform and provides strict Clean Architecture checks.
The JaCoCo Gradle plugin is built into Gradle; its agent and report tool are
pinned to `0.8.15` for Java 25 coverage evidence.

The existing test-only Swagger Parser `2.1.34` and NetworkNT JSON Schema
Validator `1.5.6` remain pinned and isolated from production classpaths for the
T036 contract-validation harness.

Flyway core, its PostgreSQL database module, and the PostgreSQL JDBC driver are
BOM-aligned verification-only dependencies. They allow the separately owned
migration and PostgreSQL integration suites to execute forward-only migrations
without adding blocking JDBC to the production runtime. Production persistence
contains only the reactive PostgreSQL client; migration execution and
credentials remain a separately governed operational boundary.

## Reproducibility and SBOM impact

Dependency locking applies to every resolvable configuration. The lock state is
stored at `gradle/dependency-locks/gradle.lockfile` and is refreshed only by an
explicit reviewed `./gradlew --write-locks dependencies` invocation. Ordinary
builds consume, but do not rewrite, that state.

The added runtime capabilities appear in the CycloneDX SBOM generated by the
Quarkus build. Test-only validators, Testcontainers, ArchUnit, and JaCoCo are
verification inputs and are not application runtime dependencies. Independent
license, vulnerability, lock consistency, and SBOM approval remains assigned
to the dependency supply-chain gate.
