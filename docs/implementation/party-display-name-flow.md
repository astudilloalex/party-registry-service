# Party canonical display-name flow — T040/T041

This is the test-first Domain/Application flow contract for T041 and the later PostgreSQL adapter task. It maps frozen OpenAPI names to the final DBML while remaining neutral about transport DTOs, persistence records, SQL, constructors and database defaults. Canonical derivation is exclusively the existing `DisplayName` domain policy.

## Triggering T012 finding closure contract

| Current T012 finding | Meaningful red assertion | Flow-map rows |
|---|---|---|
| `PartyMutationIntent` has no canonical display-name carrier | Each successful create/update spy searches the one boundary-neutral intent for `canonicalDisplayName` or `displayName` and compares it to the exact existing domain-policy result | Four create/update scenario rows |
| `CreatePartyUseCase` sends the unprocessed command | Create spies require canonical value together with Party type, matching detail kind, unchanged source details, tenant, actor, version and outbox identity | Natural-person create; legal-entity create; tenant/audit; version; outbox rows |
| `UpdatePartyDetailsUseCase` sends raw details | Update spies require canonical value together with matching source details and expected aggregate version in the same unit-of-work argument | Both detail update; version; outbox rows |
| Adapter-side derivation would violate architecture and DBML ownership | Expected values come from `DisplayName.forNaturalPerson` / `forLegalEntity`; tests observe the value before the outbound port and reject mismatch/blank input before persistence | All source/consistency rows |
| Source-name and display-name updates must be atomic | Each success case permits exactly one mutation-and-outbox port call and inspects source, canonical, tenant, version, actor and outbox facts in that call | Version and outbox/atomicity rows |

T041 completes the application flow with `PartyCreationMutation` and `PartyDetailsMutation`. Required inputs and type/detail consistency are validated first, the existing domain policy derives the canonical name second, optional Geographic Reference evidence completes third, and the single atomic Party/detail/display-name/outbox unit-of-work call is last. No adapter derives or repairs a display name.
